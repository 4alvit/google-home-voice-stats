# Governance and maintenance

The primary maintainer, 4alvit, owns roadmap and release decisions, reviews changes and coordinates private vulnerability reports. Contributors propose changes through public issues and pull requests, add relevant tests, and respond to review. Reviewers check behavior, security boundaries and test evidence; maintainers use normal protected-branch review and CI before merging. Release operators must follow RELEASING.md and preserve the documented device acceptance requirements.

Decisions and their reasons belong in the relevant issue or pull request. Disagreements can be raised there or privately through the Code of Conduct contact. This is a small maintainer-led project without a separate steering body.

There is currently no backup maintainer and no tested arrangement to restore repository, CI and release access within one week if the primary maintainer is unavailable. Automated accounts are not a substitute for that person. These OpenSSF Silver continuity requirements remain unmet.
